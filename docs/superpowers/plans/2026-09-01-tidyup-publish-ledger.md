- 2026-09-01 — Task 3 (A8, promote button + References tab behind developerMode): `src/ui/tabs.ts` doesn't exist — `createTabs`/`Tabs` actually live in `src/ui/modal.ts`. Its `Tabs` interface only exposed `{ el, show(id) }`; the per-tab `<button>` elements are private inside the `createTabs` closure (a `Map`), and no `body.dev-mode` CSS rule exists anywhere in `styles.css` today — every other developer-mode gate (`ratingBox.hidden`, `dataRow.hidden`) is JS-driven, not CSS. So neither of the brief's two preferred options was clean: no exposed buttons for a `hidden` toggle, and no established CSS-gate convention to extend safely (plus a CSS rule would need a selector unique to the References button, which the shared `.tab-btn` class doesn't offer without restructuring `createTabs`). Took the brief's third option: added `setHidden(id: string, hidden: boolean): void` to the `Tabs` interface and its `createTabs` implementation (looks up the button in the existing `buttons` Map and toggles `.hidden` on it — mirrors the JS-hidden idiom already used everywhere else). `applyDeveloperMode` now does `promoteBtn.hidden = !on; instructionsTabs.setHidden("references", !on); if (!on) instructionsTabs.show("instructions");` — the unconditional `show("instructions")` on turn-off is a harmless superset of "only switch away if References was active" (there are only two tabs, and it's a no-op if Instructions was already showing), and avoids needing an `activeId()` getter the `Tabs` interface doesn't have.
