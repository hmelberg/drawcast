drawcast

drawcast turns a sentence into a drawing that draws itself while a voice explains it — a little illustrated lecture instead of a static figure. You describe what you want, the AI writes a spec, and the player performs it stroke by stroke.

Getting started

  1. Open ✨ Examples in the sidebar and click one — it loads and you can press play immediately. Nothing needs to be set up for this.
  2. To make your own, type what you want in the box at the top and press Generate with AI. This needs an Anthropic API key, which you add under ⚙ Settings.
  3. To change it, describe the change in the same box and press Revise with AI — the whole drawcast goes over and comes back revised. You can also edit the spec text in the left pane and press Re-render.
  4. Nothing needs saving: every change goes straight to your Library (stored in this browser). The ◀ ▶ arrows walk back through this session's versions and Restore brings one back as the newest — no version is ever deleted. + New drawcast clears both sides and starts over.

Everything except AI generation works without any key: loading examples, hand-editing specs, playing, and saving to the library.

Player and editor

The ▶ Player shows nothing but the drawing — the title is drawn into the figure and the controls fade away while it plays. Press ✎ Edit at the right end of the control bar to come back to the workbench.

The ✎ Editor has three parts: the request box on top, the spec text on the left, and the live preview on the right. Each pane carries its own buttons — the spec pane handles re-rendering, downloading and uploading the source; the preview pane handles the output (video export, and marking a drawing as a reference). Where drawcast has been given a Google client id, the spec pane also gets ☁ Open and ☁ Save, which read and write that same spec straight to your Google Drive — the first click is what asks you to sign in.

Writing a request

Write what you want explained, not what you want drawn. drawcast is at its best when the request names one idea and an audience: 

Show the deadweight loss from a tax, with shaded regions

Explain diminishing marginal utility to a first-year student #basic #short

Show how a rent ceiling creates a shortage #norwegian #calm

Three quiet choices sit under the Generate button. Template forces a particular figure type instead of letting the AI choose. Instructions selects which set of authoring rules the AI follows. Model trades speed against quality — repair rounds always run on a fast model regardless.

Directives (#tags)

A #tag anywhere in your request changes what the AI writes. It never changes how the app plays back — speed, narration and mode stay in the controls. Recognised tags are stripped from the text before it is sent; anything else starting with # is left alone and passed through as ordinary words. Type # in the request box to get the list inline.

Language#norwegian (#nb, #norsk) #english (#en)Narration and labels in that language.

Style#qadialogue: one asks and reacts, one answers and draws

Structure#template=free_bodyForce one template. This beats the Template picker.

Tags in the same group override each other and the last one wins, so #short … #long gives you a long one. A tag must stand on its own — #parts and #template only work with a value after =. A request made only of tags is refused: there has to be something to draw.

Templates

A template is a ready-made figure type that computes its own geometry — you supply parameters, it works out where every line goes. Ask for a supply-and-demand diagram and the AI fills in supply_demand's parameters rather than placing coordinates by hand, which is why those figures come out correct.

Built in and always available:

TemplateDraws
supply_demandPrice–quantity market diagram: equilibrium, ceilings and floors, taxes, shifts, surplus regions.
decision_treeLeft-to-right decision tree — decisions square, chance nodes round, terminals triangular, with probabilities and payoffs.
qaly_profilesUtility against age or time, one curve per scenario, with the QALYs gained or lost shaded between them.

molecule_3dBall-and-stick 3D molecules (methane, water, ammonia, CO₂), rotatable, with an “Explore in 3D” button.
two_by_two_table2×2 contingency table — sensitivity/specificity, a confusion matrix, a payoff matrix, or any two-binary-factor comparison, with an optional highlighted cell.

More arrive in packs — Physics (lens ray diagrams, wave diagrams), Chemistry (molecules drawn from SMILES, reaction schemes, energy diagrams), Biology (membrane bilayer, DNA helix, phylogenetic trees from a Newick string), Economics (consumer choice, PPF, cost curves, payoff matrices, AD-AS), Evidence & epidemiology (survival curves, forest plots, causal DAGs, epidemic compartments) and Math & logic (Venn diagrams, the unit circle, truth tables, argument maps, handwritten equations), and more besides — Data charts & tables, Size comparisons, Anatomy, Space and others. They are on by default. Two more ship in the box but start off: Games (chess positions and replayed lines) and Maps (hand-sketched country outlines) — switch either on the same way. Toggle any pack under ✦ Templates → Packs, which also takes it out of what the AI is offered. Marking a pack as Default domain matters only once the library outgrows the point where every template still gets a full entry — then its templates keep theirs.

size_compare picks the drawn size from the numbers: measure says what the value is (diameter, length, area, volume, mass), layout how they stand (beside, row, inside, overlay), and count_fit fills a row with copies of the small one: 

{ "template": "size_compare",
  "params": { "items": [ { "name": "Sun", "value": 1392700, "unit": "km" },
                         { "name": "Earth", "value": 12742, "unit": "km" } ],
              "measure": "diameter", "layout": "inside", "count_fit": true },
  "commands": [
    { "draw": ["sun_shape", "sun_label"], "speak": "The Sun, drawn to scale." },
    { "draw": ["earth_shape", "earth_label"], "speak": "And the Earth, to the same scale." },
    { "draw": ["fit_row", "fit_label"], "speak": "A hundred and nine Earths would fit across it." } ] }

Anything the templates do not cover is drawn from primitives instead — axes, curves, points, arrows, labels, regions. You are never limited to this list; templates just make the common cases exact.

Making your own

✦ New template… (in the Template picker, or in the Templates modal) describes a reusable figure to the AI — in words, or by pasting a reference image — and saves the result under My templates. You can refine it, improve it later, and export it as a .yaml file to share.

Templates are code. A template's layout is JavaScript that runs in your browser with access to everything this page can reach, including your stored API key. Import a template file or load a remote pack only from a source you trust — treat a pull request to a template repository as a code review.

Instructions and references

Instructions are what the AI is told before your request: the rules for how a drawcast should be built, which verbs to use, and how to pace narration. The bundled set is read-only; “Copy to my prompts” makes an editable version, and Improve with AI proposes a revision based on your worst logged generations — always saved as a new set, never overwriting.

If you edit instructions, the placeholders {{SCHEMA}}, {{CATALOG}}, {{FEWSHOTS}} and {{EXEMPLARS}} must stay in the text. They are filled in at generation time with the spec schema, the template catalogue, the built-in examples, and your own references.

References are the second tab, and the simplest way to improve your results. Press 👍 Learn from this under a drawing you like and the pair (your request, the resulting spec) is shown to the AI as an example of what you want from then on. A few good references shift the style of everything generated afterwards. Remove one and its influence disappears with it.

The spec format

A drawcast is a small document with a list of commands. The editor shows it as a .cast script, and that is what Publish writes. YAML and JSON are read too, and ⬇ Download can save a single drawcast in any of the three. They all hold the same fields, so the YAML below and a script say the same thing. You can read and edit the text directly; the preview re-renders on Re-render. 

title: Demand increase
template: supply_demand
params:
  demand: { label: D }
  supply: { label: S }
  equilibrium: { show: true, guides: true }
commands:
  - speak: Let's build a market diagram and find where the price settles.
  - draw: [axes]
    speak: Price on the vertical axis, quantity on the horizontal.
  - pause: 0.3
  - draw: [demand_curve, label_D]
    speak: 'This falling line is demand: as price falls, quantity demanded rises.'

The top level holds:

FieldMeaning
titleShort title. It is also the page's heading unless you say otherwise (see The page).
headingfalse for no heading, or other words for the heading than the title.
page{ valign: top } or none stops the figure being centred vertically.
affirmWhat a viewer hears after a right answer (see Replies).
templateWhich template computes the geometry.
paramsThat template's parameters.
elementsHand-placed pieces when no template fits: axes, curve, point, arrow, label, region, node, edge, annotation, path, text, shape.
domainCoordinate ranges, as { x: [0, 100], y: [0, 100] }.
levelbasic or advanced — shown as a badge.
commandsThe performance itself. The only required field.

The drawing area is a logical canvas of 1000×750, Cartesian, y-up, with the origin at the bottom left. Any element you never mention in a command is drawn automatically at the end.

Command reference

Each command does one thing, and may carry a speak line alongside it. When it does, the voice and the action start together and the command ends when both are finished — that is what keeps narration in step with the drawing.

CommandWhat it does
speak: "…"One narrated sentence, also shown as a caption. Add blocking: false to start it and carry on immediately.
draw: [ids]Hand-draws those elements in order; parallel: true draws them at once.
show: [ids] / hide: [ids]Appear or disappear instantly, no animation. Hidden things can come back.
erase: [ids]Un-draws in reverse, then stays hidden.
clear: {}Hides everything visible. clear: { keep: [ax, curve] } spares what you list — list everything that should stay.
pause: 0.5Silence, in seconds. A beat after a reveal is worth more than it looks.
wait: clickStops until the viewer clicks. Auto-resolves in video export.
quizA multiple-choice question card (skippable unless required: true). Several in a row make a test. In a video the card hovers over the options and picks the right one by itself. on_canvas, reveal and confidence are in Questions.
askA typed-answer question. With answer it is checked (optional retry/reveal); with store + default the reply is saved and later narration can say it back with {name}. In a video the card types its answer by itself. Guessing on the figure, ordering, spotting, estimating and polls are in Questions.
label / gotoslabel names a position; right_goto/wrong_goto on quiz and ask jump there on a viewer's answer — a wrong answer can replay the explanation and ask again. if jumps on a stored answer ({"if": {"var": "age", "gt": 20, "goto": "…"}}). Videos always play straight through.
exploreHolds the lesson for the viewer: with a pane: controls script the drawn knobs are live and the tray stays shut — press ▶ or click the figure to continue; otherwise the ⊕ tray opens. On a script with controls the beat first plays a demo of the knobs — a short walk of its own, or the sweep play: {"values": {…}} plans — and hands the panel over afterwards; play: false drops the demo. A video keeps that demo and the beat's narration, and skips only the waiting; a beat with no controls script is still skipped whole. The ⊕ also pulses after any personalized animation. An explore naming a script with controls opens those controls.
runPlays a controls script through a series of values without handing the lesson over: {"run": {"code": "sim", "values": {"rate": {"from": 1, "to": 9, "steps": 5}}, "every": 1.2}}. A value may hold (rate: 4), step through a list ([1, 4, 9]), or sweep a range; every is seconds per step and loop repeats the series. Controls the sweep does not name stay at their defaults, and a shorter list holds its last value. The paired speak plays over the sweep — in the app and in the movie alike — and the script stays where the sweep left it: a knob afterwards continues from there, and only a scrub back past the run restores the author's script.
widget (on ask)Answer on the figure instead of typing: click — click the named element; piano — press a key on the drawn keyboard (it sounds, and a paused piano is always playable); chess — click a move's from- and to-squares. Videos demonstrate with the laser pointer. A template with a widget body (Morse key, Tower of Hanoi, logic gate, xylophone, bubble sort, tic-tac-toe — the Widgets pack) can be the device too: widget: morse_key lets the viewer work the figure and the widget's own answer is judged; paused, such a figure is always playable. A widget may also take keys (Morse: hold space) and drags — press a part and pull it, and it follows the pointer until you let go (drag a Hanoi disk onto a peg, a bubble-sort bar onto its neighbour); clicking the two parts in turn always works too.
controls (on code)Names script variables the viewer can change from the ⊕ tray: a range tuple n = (1, 50) becomes a slider (integers when written without decimal points), a list of strings a choice row, True/False a switch, a string a text field, a number a number field, and Slider(1, 50, default=10, label="Cycles"), Choice(…), Toggle(…), Text(…), Number(…), Button("Draw again") when a label or default is wanted — also as a function's default argument, and in R with c(1, 50). Moving a control rewrites that line and re-runs the script; the panel and any chart it feeds update. Continue restores the lesson. With pane: controls the pane draws the knobs instead of the code, and the drawn knobs are the controls: while paused, drag a slider, click a chip or a switch, or click a box to type. A click on the panel while the lesson plays pauses it on the same press. autorun: false adds a drawn Run ▶ row. The movie shows the panel at its defaults, or wherever a run or the explore demo left it.
Personalized figuresAn animate value can be a stored answer: {"animate": {"n": "{n_choice}"}} glides the template param to the viewer's own number (the ask's default is the movie's value). Try the "Your own sample size" example.
{score}Reserved variables {score} and {score_total} keep a running tally of answered questions — usable in narration ("You got {score} of {score_total}!") and in if conditions. Skipped answers count as wrong; re-answering after a jump overwrites, never double-counts.
intro (on quiz/ask)A spoken introduction that lives inside the question — so skipping questions (a Settings switch) skips the introduction too.
point: { at: {ref: id}, gesture: tap }A pointing gesture — tap, circle or underline. at takes a ref or an x/y.
highlight: { target: [ids], effect: pulse }Emphasis: pulse, circle or glow. Paired with a speak and no duration, it lasts the whole sentence.
move: { target: [ids], by: [dx, dy] }Slides elements; path for several legs, plus duration and easing. Only the listed elements move.
camera: { center: {ref: id}, zoom: 2 }Zooms and pans; reset: true returns to the full view.
animate: { "demand_shift.amount": 22 }Smoothly changes template parameters over duration seconds — a curve that visibly slides while the voice explains it. Template specs only.

Seeking is a control, not a command: drag the progress bar to jump to any point.

The page

Every page has the same frame: a heading strip along the top, the content area in the middle, and a band at the bottom kept clear for the captions. The engine composes the page inside that frame, so you describe what is on it and leave the placing to it.

A heading by default

A page with no card command draws its title as the heading — quickly, unnarrated, with the first ink. Say heading to change that: 

{ "title": "Why is the sky blue?", "heading": "Rayleigh scattering", … }   // other words
{ "title": "Why is the sky blue?", "heading": false, … }                   // no heading

A card command still works when you want the heading spoken or the slower centre card. Leave a template's own title parameter unset, or you get two headings.

The figure fills the page

A figure that is alone on the page grows into the content area — cards, number lines, pie charts, size comparisons and templates that lay out in a box. With company it keeps its share. Text a viewer must read (card words, tick numbers, chart labels and values) starts at a readable size, wraps onto a second line before it shrinks, and shrinks only to avoid a collision. If a figure still ends up small on an empty page, the check says so.

Centred between the heading and the captions

When the figure sits clearly off-centre in the content area, it is moved as one piece so the space above and below is even. Pages whose figure moves, morphs or animates are left as laid out. The hatch: 

"page": { "valign": "top" }    // center (default) · top · none
What you no longer do by hand: add a card just to get a heading, nudge coordinates to centre a figure, bump font_size so labels can be read, size cards, or keep things clear of the captions. When you do want control, the hatches are heading, page, cards size, number-line ticks/tick_format, a template's box, an element's x/y/width, and the top-level text.font_size.

Cards

A cards element is a set of paper cards the viewer orders, sorts or places. They size themselves: size: "auto" (the default) grows them, up to 1.6×, when they are alone on the page; a number from 0.6 to 2 sets the size yourself. Card words wrap onto two lines before they get smaller. 

{ "id": "kill", "type": "cards", "size": 1.3, "ends": ["most", "least"],
  "items": ["Heart disease", "Stroke", "Chronic lung disease"] }

A label attached to a card, and a compare card's value, travel with the card when it slides; hiding the set hides them too. Card and guess questions finish with Done.

Place on a line

Give the cards along (a number line's id) and each item a value. While a card is dragged over the line, a pin shows the exact value it would land on. After Done, each card glides to its true place and leaves a faded ghost at yours, so the two can be compared while the explanation runs. 

{ "id": "years", "type": "scale", "min": 1800, "max": 2000, "label": "Invented" },
{ "id": "inv", "type": "cards", "along": "years",
  "items": [ { "text": "Telephone", "value": 1876 }, { "text": "Aeroplane", "value": 1903 },
             { "text": "Internet", "value": 1983 } ] }

{ "draw": ["years", "inv"], "speak": "Three inventions, and two centuries to put them on." },
{ "ask": { "question": "Drag each invention to the year it was made, then press Done.",
           "on": "inv", "store": "p", "right": "{p.within} of {p.total} close." } }

Number lines

A scale element is a number line to guess on. The engine places it on the page; its ticks are large enough to read and thin out when crowded.

  • Big numbers in words. Ticks read “43 million”, “1 billion” — up to quintillion, then 10ⁿ — and the voice says them the same way. On a log: true line that spans powers of ten, this is what keeps it readable.
  • BC years. A year line that reaches back past year 0 writes “3000 BC” and “AD 500”. era: "BCE" writes BCE and CE instead; era: "none" keeps the minus sign.
  • tick_format: words (default), numerals, or power (10ⁿ).
  • The unit is written once, on the line, not on every tick.
  • While the viewer guesses, a ghost marker shows the value under the pointer.
  • markers: other points worth naming — [{"value": 7, "label": "old limit"}]. The engine places their words over the line, clear of each other; they come with the line, or draw <id>_marker_1 on its own beat.
{ "id": "s", "type": "scale", "min": 1000000, "max": 100000000000, "log": true,
  "value": 8100000000, "unit": "people", "label": "People alive today" }

{ "id": "s", "type": "scale", "min": -3000, "max": 2000, "value": -2560, "era": "BCE",
  "label": "The Great Pyramid is built" }

{ "id": "s", "type": "scale", "min": 1, "max": 1000000000000, "log": true,
  "tick_format": "power", "label": "Stars in a galaxy" }

Charts

The data charts (bar_chart, line_chart, pie_chart and friends) draw names, values and ticks at a readable size; long category names go onto two lines. Bar and line charts get round numbers up the y axis by default — y_ticks: false leaves it bare — and a long line chart gets more year ticks. A pie on its own grows into the content area.

sort: "desc" (or "asc") keeps the bars in order of their value at the stage shown, so an animate between stages slides each bar to its new rank. bar_3 stays the third label's bar wherever it stands.

A pie starts at 12 o'clock; start_angle (degrees clockwise) turns it — 90 starts the first slice at 3 o'clock. 

{ "template": "bar_chart",
  "params": { "labels": ["Mandarin", "Spanish", "English", "Hindi"],
              "values": [[940, 485, 390, 345], [1180, 560, 1530, 610]],
              "stage": 0, "sort": "desc" },
  "commands": [
    { "draw": ["axes", "bar_1", "bar_2", "bar_3", "bar_4"], "parallel": true,
      "speak": "Native speakers first: Mandarin leads." },
    { "animate": { "stage": 1 }, "duration": 2.5,
      "speak": "Now count everyone who speaks it, and English jumps to first." } ] }

Questions

Two commands ask the viewer something: quiz (pick one of a few choices) and ask (everything else — typing, guessing on the figure, ordering, tapping). Each form below is one or two fields on one of them. In a video, every question answers itself.

Buttons on the figure

on_canvas: true draws a quiz's choices as buttons beside the figure — no card pops up, and the question is not said again, so say it in the line before. Made for True/Myth and yes/no runs over a picture. Optional: buttons (each choice's text and icon), buttons_at (their centre), buttons_layout (row or column), say_question: true, keep_buttons: true, and id (the buttons are <id>_btn_1, …). 

{ "draw": ["moon"], "speak": "The Moon is drifting away from us. True, or myth?" },
{ "quiz": { "question": "The Moon is drifting away from us.", "choices": ["True", "Myth"],
            "correct": 1, "on_canvas": true, "buttons_layout": "column",
            "reveal": "3.8 cm a year",
            "right": "True: it moves about 3.8 centimetres further away each year." } }

Reveal stamps

reveal on a quiz or an ask stamps the verdict beside the figure as the right line is spoken: true stamps the right choice's words (“MYTH”), a string stamps those words. The long form is { "text", "at", "color", "size", "style": "stamp" | "label", "keep" }, where at is an element id or {x, y}. The stamp goes when its figure is hidden — so never draw a verdict yourself after the question. 

"reveal": { "text": "3.8 cm a year", "at": "moon", "style": "stamp" }

A run of pictures

A sequence shows things one at a time: the current one large in the middle, the finished ones waiting small in a strip. Items are {icon, label}, {text, label} or the id of something you drew; a mark (a word, or {text, color}) appears under each in the strip once done. Draw <id>_1, <id>_2, … in turn, and <id>_strip to bring the row back as a recap. Also strip (top, bottom, none), show_upcoming: "dots" and recap: false. An item may carry cites (ids from sources): its picture and name then open the study on their info card, as any element's do. 

{ "id": "sleepers", "type": "sequence", "items": [
    { "icon": "horse", "label": "Horse", "mark": { "text": "Yes", "color": "#3f7d4e" } },
    { "icon": ["cow", "cow face"], "label": "Cow", "mark": { "text": "No", "color": "#b5482e" } } ] }

{ "draw": ["sleepers_1"], "speak": "First the horse." },
{ "quiz": { "question": "Can a horse sleep standing up?", "choices": ["Yes", "No"],
            "correct": 1, "on_canvas": true, "right": "Yes: its legs lock, so it dozes on its feet." } },
…
{ "draw": ["sleepers_strip"], "speak": "You got {score} of {score_total}." }

Odd one out

Cards with one item marked odd: true and a rule saying what the others share. The viewer taps one; the odd one is ringed and the rule is written under the cards. Three to six cards. Over things already drawn, use choose + answer + rule on the ask instead. 

{ "id": "zoo", "type": "cards", "rule": "All four are mammals; the shark is a fish.",
  "items": [ { "text": "Whale", "icon": "whale" }, { "text": "Bat", "icon": "bat" },
             { "text": "Dolphin", "icon": "dolphin" }, { "text": "Shark", "icon": "shark", "odd": true } ] }

{ "ask": { "question": "Which one is not a mammal? Tap it.", "on": "zoo",
           "right": "The shark: a fish, with gills and no milk." } }

Spot it

The viewer taps a place on a picture and is judged on its outline, which is drawn at the reveal. spot is a region of an image, a template part (an organ, country_norway) or any drawn id. Draw the place first, without naming it. 

{ "ask": { "question": "Where is the liver? Tap it.", "spot": "liver", "on": "anatomy",
           "right": "There: under the right ribs.", "wrong": "Look higher, and on the body's right." } }

Estimate

A lone number with no figure to guess on: a big counter over a slider, scored by how close the guess is. The ask draws it itself (erase it later as estimate_1). It takes unit, log, label, tick_format and era like a number line. 

{ "ask": { "question": "How many bones does an adult have? Drag the slider to your estimate.",
           "estimate": { "min": 0, "max": 500, "value": 206, "unit": "bones" },
           "store": "g", "default": "150",
           "right": "Close: you said {g}, it is {g.true}.", "wrong": "You said {g}; it is {g.true}, {g.off} away." } }

Put the steps in order

Cards with steps: true get numbered slots, first to last; once they stand in the true order, arrows draw in between them. List the items in their true order — they are shuffled on screen. 

{ "id": "cosmos", "type": "cards", "steps": true, "ends": ["first", "last"],
  "items": ["Big Bang", "First stars", "Sun forms", "Earth forms", "First life"] }

{ "ask": { "question": "In what order did these happen? Drag the earliest to the first place.",
           "on": "cosmos", "store": "k", "right": "{k} in place.", "wrong": "You got {k}." } }

How sure are you?

confidence: true on a quiz (or on an ask with choose and answer) adds a bet after the pick — 50/50, Fairly sure, Certain. Over a run of questions, {calib} says how well calibrated the viewer was (“a bit overconfident”) and {calib.score} gives it out of 100. 

{ "quiz": { "question": "How long does sunlight take to reach Earth?",
            "choices": ["8 seconds", "8 minutes", "8 hours"], "correct": 2,
            "confidence": true, "right": "About eight minutes and twenty seconds." } },
{ "speak": "You were {calib}: {calib.score} of 100." }

Poll and compare

An opinion with no right answer, compared with what the people in a real study chose. Give 2–4 choices with each one's share (a fraction) and the study in sources; {p.share} is the share who chose as the viewer did, {p.most} the commonest choice. On a number line instead: "poll": { "on": "<scale id>", "others": [{ "value": 40, "share": 0.3 }, …] }. 

{ "ask": { "question": "How many of the 100 kroner do you offer the stranger?",

Before and after

A first guess kept back (reveal: false), some new evidence, then a second guess with revise naming the first. The viewer starts from their first guess and sees both against the truth; {g2.moved} is how far they moved.

Icons

An icon stamps a named thing; you write only the keyword and the app fetches the artwork. For something rare, give fallbacks — the thing first, plainer stand-ins after, tried in order. Multi-part drawcasts

Add #playlist (or #parts=4) to a request and you get a sequence of drawings that play in order. A playlist title opens the show as a fading title page. Between parts the finished drawing stays on screen with a “Click to go on to …” button, then un-draws itself; where a new chapter begins, a chapter card announces it. In text form it is a stream of YAML documents separated by ---, with an optional header: 

playlist:
  title: A short course on taxes
  subtitle: In six drawings   # optional, under the title on the title page
  advance: auto      # or click, to wait for the viewer at each part
  gap: 1             # seconds between parts when advancing automatically
  transitions: auto  # auto = soft fades + chapter cards, none = hard cuts
---
chapter: Foundations
---
title: Supply and demand
commands: [ … ]
---
title: A tax drives a wedge
level: advanced
commands: [ … ]

A chapter: document groups everything that follows it until the next one. During playback, dots in the control bar jump between parts, n and p step forward and back, and the ☰ button opens a list with the chapters.

Sharing a drawcast

Paste a spec into a Google Doc, share the doc as Anyone with the link can view, and hand out a drawcast link with the document's id after #gdoc=: 

https://drawcast.app/#gdoc=1AbC…xyz

That link opens a player and nothing else — no editor, no AI, no key needed by whoever opens it, and the editor code is never even downloaded. Because the drawcast lives in the doc, you can fix a typo there and everyone's link shows the correction. Options can be appended:

Pretty links and the name service

Every published drawcast has a free, permanent address: the link Publish shows, with the file's location inside it (drawcast.app/#gh=…). A pretty link is a short name on top of that: drawcast.app/#name, which also answers as name.drawcast.app. The name is a pointer kept by the drawcast server: it resolves to wherever the work is published — GitHub, the drawcast server or Google Drive — so a republish never breaks the link, and a name once registered goes on working even after you change to another. Only a registered name opens anything; an unknown name says so.

You buy a pretty link under ↗ Publish → Pretty link, for a drawcast or a course, once you have published it somewhere: the panel lists the copies the name can point at, and Check tells you whether a name is free and what it costs. The price follows the name's length: 20 USD up to 5 characters, 10 USD up to 7, 5 USD from 8 (at least 3). You pay on Stripe's page and land back here with the name registered. A course's pretty link points at its course page; the folder its lectures live in never moves. Renaming buys the new name; the previous one goes on working.

Terms. Registering a name is a one-time contribution to drawcast, not a subscription. It registers the address to your account for as long as drawcast operates. drawcast is a free research project and offers the service as-is: no guarantee of uptime, of the address continuing to resolve, or of the service existing in the future. No refund is made once the name is registered. If the name cannot be registered after payment because someone else took it in the meantime, the payment is refunded.

Video export

🎬 Export video records the drawcast as a narrated 720p WebM file, which YouTube accepts directly (Studio → Create → Upload). A playlist becomes a single video with its title cards included, and wait: click resolves by itself since there is nobody to click. Where drawcast has been given a Google client id, ▶ YouTube uploads that same file to your channel straight from drawcast — it asks you to sign in when you press Upload — but every upload lands private, whatever visibility you pick, until drawcast has passed YouTube's compliance audit.

This needs a Google Cloud Text-to-Speech key, added under Settings — browser speech cannot be recorded, so the narration has to be synthesised. The recording happens in your browser in real time, so a three-minute drawcast takes about three minutes, and silently — the narration goes into the file, not your speakers. It runs in the background: a 🎬 progress chip appears above the drawing (its ✕ cancels), and the recording keeps going while you work elsewhere — in drawcast, in other tabs, in other apps, even with the browser minimized.

A command's delivery hint (grave, brisk) subtly varies that line's voice, and #male/#female choose the narrator (the lead speaker, or speaker "a" in a dialogue).

A word in another language. Mark it in the narration and it is spoken by a voice of that language, of the narrator's own sex: Here is a German word: [de:ich]. The tag is a language code or its English name, so [french:c'est la vie] and [fr:c'est la vie] are the same thing. The caption shows just the word — the brackets are an instruction to the voice, never something a viewer reads. If you have picked a voice for that language under Settings → Playback, that is the one used.

The named languages are English, Norwegian, Danish, Swedish, Finnish, German, Dutch, French, Spanish, Italian, Portuguese, Polish, Russian, Turkish, Arabic, Hindi, Japanese, Korean and Chinese. For any other language, write the full locale — [cs-CZ:ahoj], [el-GR:γεια] — in the same form the voice catalogues use; it is passed straight through, so a browser or a cloud voice that has that language will speak it. Bokmål is nb or nb-NO, not no-bm.

A bare tag has to be one of the named languages, because see, it and no are ordinary words as well as language codes — so [see: figure 3] stays in the sentence exactly as written, and so does [see-also: page 9].

Keys and privacy

drawcast has no server of its own. Everything you make lives in this browser's local storage — your library, templates, instructions, references and both API keys — and nothing is uploaded anywhere.

  • Anthropic API key — needed only to generate with AI. It is sent directly from your browser to api.anthropic.com, never through anyone else.
  • Google Cloud Text-to-Speech key — needed for video export, and optionally for nicer voices during normal playback. Sent only to texttospeech.googleapis.com. Google's free tier of roughly a million characters a month covers about a thousand drawcasts.

Because it all lives in one browser, clearing site data erases your work. Use ⬇ Download to keep a spec as a file, and export templates you care about as .yaml.

Troubleshooting

“Add your Anthropic API key in Settings”

Generation is the only feature that needs a key. Examples, editing, playback and saving all work without one.

A label overlaps something, or a piece sits outside the frame

The ⚠ chip above the preview appears when the layout has problems and lists them when clicked. Most are fixed by shortening a label, or by giving the element more room in the spec. When the chip is absent, the layout checked out clean.

The figure looks small, or there are two headings

A figure alone on the page grows by itself; one that does not (a hand-placed group, an icon with a fixed size) can be given more room — cards size, a template's box, or a larger width. Two headings mean the title is drawn twice: leave the template's own title parameter unset, or set heading: false. See The page.

The drawing ran ahead of the narration

Put the speak on the same command as the action rather than on its own line — paired that way, the command waits for both to finish.

Something vanished mid-drawcast

A clear hides everything not named in its keep list. List every element that should survive, or use erase on the few things you actually want gone.

The share link says it cannot fetch the document

The Google Doc has to be shared as Anyone with the link can view (Share → General access). A doc restricted to specific people cannot be read by the viewer.

The AI ignored my template choice

A #template= directive in the request beats the Template picker. Also check that the template's pack is enabled — a template that is not switched on is not offered to the AI.
